# Проверка первого парсера на расширенном датасете

## Результат

Первый RegEx-парсер проверен на 80 синтетических договорах версии 2.

| Метрика | Точность |
|---|---:|
| Все 5 полей документа извлечены верно | 25,0% |
| Номер договора | 40,0% |
| Дата заключения | 55,0% |
| Заказчик | 25,0% |
| Исполнитель | 36,25% |
| Сумма | 47,5% |

На первых 20 простых документах парсер по-прежнему работает точно. Снижение на полной выборке ожидаемо: новые договоры используют отраслевые названия сторон, таблицы, приложения, разные форматы дат и нетипичное расположение реквизитов.

## Что улучшать дальше

1. Сначала определять роль стороны по словарю синонимов: покупатель/поставщик, арендатор/арендодатель, принципал/агент и т. п.
2. Искать номер, дату и сумму не одной регуляркой, а собирать несколько кандидатов с весами по контексту.
3. Обрабатывать таблицы DOCX отдельно, сохраняя связь между названием поля и соседней ячейкой.
4. Разделять основной договор и приложения, но учитывать сумму из спецификации, если в основном тексте её нет.
5. Добавить набор отрицательных примеров, чтобы не принимать сроки, номера приложений и промежуточные платежи за нужные реквизиты.

Подробные построчные результаты находятся в `baseline_results_v2.csv`.
